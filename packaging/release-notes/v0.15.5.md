fastframe 0.15.5 tells an app why an update rolled back, and keeps logs and private files to their user.

Move every fastframe crate to `tag = "v0.15.5"`. Apps need no code changes. An app that wants the reason reads the new `Launch::failure`, and an app that compares `Launch::error` with its text should compare it with `Launch::RESTORED`, whose wording changed.

## New

- **A restored app learns why the update failed.** `Launch::failure` holds the failed step and reason, including how the new version exited (`exit status: 1`, `signal: 9`), for the app's log or error reports. It can name folders on the computer, so it is not for showing to the user. Helpers older than this release send none. (`--update-failure`)

## Fixed

- **The rollback message says what to do.** It now reads "The update did not finish, so nothing changed. Restart to try again." It also covers a failure before the new version opened, which the old "could not start" did not.
- **Private writes make private folders.** A private write now creates missing folders with mode 0700 on Unix. By @igor-alexandrov. (#32)
- **Logs belong to their user.** On Unix the log and the panic log are created with mode 0600 in folders with mode 0700, and a log an older version left readable is made private when opened. By @igor-alexandrov. (#33)
