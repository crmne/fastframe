fastframe 0.4.1 fixes what the apps found when moving onto 0.4.0. A macOS app started in the background no longer takes focus when its menu-bar item appears. A second launch is told at once when the running copy declines its request. The tray moves to tray-icon 0.25.

Upgrade by moving the tag on every fastframe crate:

```toml
fastframe-tray = { git = "https://github.com/crmne/fastframe", tag = "v0.4.1" }
```

Two changes may be needed when moving the tag:

- **Handle `Claim::Declined`.** An app that matches on `fastframe_instance::Claim` adds an arm for it, which can do what `Running` does.
- **Move tray-icon to 0.25.** An app that depends on `tray-icon` itself, for its own muda menus such as a macOS menu bar, moves it to `0.25` too. The tray and the app share muda's process-wide menu handler, so they must use the same version.

## New

- **The macOS menu-bar item can be made without bringing the app forward.** `Tray::create_item()` makes it for an app that starts with no window, such as in the background at login. `attach()` makes it too but also activates the app, so an app started at login took focus from the one in front. Elsewhere the item exists from `spawn`, and `create_item` does nothing. By @crmne.
- **A declined request is told apart from a silent copy.** When the running copy's handler returns `None`, it now answers that it declined. `claim` returns `Claim::Declined` at once, and `send` returns a `PermissionDenied` error. Before, the second launch waited three seconds and reported the running copy as not answering. Copies from 0.4.0 stay silent, as before. By @crmne.

## Fixed

- **The macOS tray icon is sharp.** The menu bar draws 18-point icons, 36 pixels on Retina screens. The tray asked for 32, so template images were scaled up and soft. By @crmne.
- **A running copy that cannot listen no longer blocks every later launch.** Binding the socket can fail, for example when its path is longer than the system allows. The running copy then kept the lock with nobody listening, so every later launch waited and gave up. It now lets the lock go and runs unguarded. By @crmne.
- **fastframe-tray uses tray-icon 0.25 (muda 0.20).** An app already on 0.25 is no longer pulled back to 0.24. By @crmne.

## Known limitations

- **The macOS Now Playing panel and media keys still have not been watched working.** That carries over from 0.4.0; Spotifast is checking them on a Mac.
