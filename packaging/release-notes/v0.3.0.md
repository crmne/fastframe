fastframe 0.3.0 adds `fastframe-audio`, an audio output that costs nothing while paused. It wraps the app's own renderer (a rodio mixer, a kira renderer or a decoder), follows the default output, reopens after failures, and keeps a clock of what has reached the device.

Upgrade by moving the tag on every fastframe crate; nothing changes in the existing crates:

```toml
fastframe-audio = { git = "https://github.com/crmne/fastframe", tag = "v0.3.0" }
```

## New

- **A paused player uses no CPU.** rodio's output stream keeps the device asking for sound until it is dropped, so a paused player still mixed silence many times a second. `fastframe-audio` pauses the cpal stream itself: a paused output gets no callbacks at all, and `resume()` plays again within microseconds. On Linux, Spotifast's paused CPU went to 0.00%. By @crmne. (crmne/spotifast#636)
- **The output keeps itself on a working device.** `maintain()` reopens a stream that failed or whose device went away, moves to a new default output, and lets the device go after a long pause (five minutes by default). The renderer is kept across reopens and is told the new rate and channel count, so what is playing carries on from the same sample. By @crmne.
- **Errors say what to do about them.** Each error is `Fatal` (no audio system, access denied, an unsupported configuration), so the app fails what is playing, or `Recoverable` (a glitch, a busy or vanished device), so the app logs it while the output reopens. By @crmne.
- **A clock of what has played.** `Clock::played()` counts what has reached the device, less the latency it reports. It stands still while paused, never goes backwards, and carries on across reopens at another rate. By @crmne.
- **The options the apps need.** These include a preferred sample rate, a fixed buffer everywhere or only on Windows, fixed render blocks for kira, a named device that falls back to the default, and optional cpal PulseAudio and PipeWire backends. By @crmne.

## Known limitations

- **`release_after` takes effect only through `maintain()`.** An app whose audio thread sleeps while paused calls `maintain()` every few seconds during the pause, or the device stays open (still with no callbacks).
- **Tested on Linux only.** No callbacks while paused was measured on ALSA, PulseAudio and PipeWire. macOS and Windows build and pass the tests in CI, but nobody has played audio through them yet.
- **cpal 0.18 only.** cpal 0.16 and 0.17 bind a different `alsa-sys`, and two of them cannot share a Linux build. An app that also uses rodio 0.21 or 0.22's own output, or librespot's rodio backend, has to drop that output.
