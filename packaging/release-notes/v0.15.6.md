fastframe 0.15.6 lets an app download an update in the background and install it at its next start, with the same checks and rollback as any update.

Move every fastframe crate to `tag = "v0.15.6"`. Apps need no code changes. An app that wants to install at its next start calls the new `Updater::kept` early in that start and hands what it returns to `Updater::handoff`.

## New

- **A download is kept for the next start.** Every download now leaves what it verified in its staging folder (`staged.json` with the payload's hash, and the release's `checksums.txt` and `checksums.txt.sig`). `Updater::kept` finds the newest download no helper has used, for this installation and newer than the running version, and checks it again: the payload's hash, the publisher signature, and the package's listed checksum or the executable's `--version`. One that fails a check is removed. Solco uses it to install updates before its library opens instead of asking the DJ to restart. (Solco ADR 0341)

## Fixed

- **A portable Linux app with libraries beside it can update itself.** An app linked with an `$ORIGIN` run path (Solco links Dawn that way) failed the `--version` check of its download, which runs from the staging folder where those libraries are not, and its helper, a copy in that folder, could not start either. The check now finds the libraries in the installation's folder, as the installed copy will, and the helper takes copies of the `.so` files beside the app, as it already did with DLLs on Windows. On Windows the check also looks in the installation's folder. The helper that runs is the version being left, so this helps updates away from apps built with this release.
