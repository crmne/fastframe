fastframe 0.15.4 stops audio output from getting a Linux app killed when the process has no real-time CPU budget left.

Move every fastframe crate to `tag = "v0.15.4"`. Apps need no code changes.

## Fixed

- **Linux audio no longer asks for real-time with no CPU budget.** With `RLIMIT_RTTIME` at 0, which libpipewire can set and nothing can raise again, or with RTKit reporting no maximum, the output thread was made real-time and the kernel killed the whole app with SIGKILL as soon as a tick landed on it. The output now refuses real-time in that case and takes a raised nice level. By @simonbbby; thanks to the reporter of crmne/zapfast#677. (#59)
