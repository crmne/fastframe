fastframe 0.16.0 lets a copy that can't update itself say how to update, announces only releases the publisher signed, and updates AppImages by default.

Move every fastframe crate to `tag = "v0.16.0"`. **One behaviour change:** `UpdateConfig::appimage` now defaults to `true`. An app whose releases sign their AppImages in `checksums.txt` (Spotifast) updates them with no change. An app whose AppImages aren't in the signed `checksums.txt` (ZapFast and TonePush today, which list them only in `packaging-checksums.txt`) needs no change either: `check` learns the AppImage isn't signed and `installation` refuses it with the new `Unsupported::MissingAsset`, as it refused AppImages before, so it keeps telling people to update from the download page. To keep refusing AppImages outright, set `appimage: false`. To have the AppImage update itself, add it to the signed `checksums.txt`.

## New

- **Copies a package manager owns can say how to update.** `Updater::managed_update` names the package manager, the package and the command that updates it, for the app to show with a Copy button (#68): `sudo pacman -Syu <package>`, `yay -Syu <package>` (or `paru`) for the AUR, `sudo apt update && sudo apt install --only-upgrade <package>`, `sudo dnf upgrade --refresh <package>` or `sudo zypper update <package>` by distribution, `brew upgrade [--cask] <name>`, `flatpak update <app id>`, `sudo snap refresh <name>`, `nix profile upgrade <element>`, and `cargo install <crate>`. The updater never runs it. Only plain names reach a command; where the computer can't tell (no `/etc/os-release`, a crate from another registry or over SSH, Nix through NixOS or Home Manager) there is no command. A package manager that doesn't answer within ten seconds gives no answer.
- **A release can be checked without downloading it.** `Updater::verify` fetches only `checksums.txt` and its signature, checks the signature with the publisher key, and requires a download of that version for this system that the release both signs and attaches, by the same rules a download follows. `Updater::installable` then says whether this copy can install it, and refuses a release another key, source or repository verified. A copy that can't install a release should announce it only after `verify`. The crate README shows the calls.
- **AppImages update themselves by default**, and `UpdateConfig::appimage_name` names AppImages that native-packages calls after a package rather than the program (`chatwithwork-desktop-1.2.3-x86_64.AppImage` for the slug `cww-app`).

## Fixed

- **A download whose file the release doesn't sign is not a failed update.** (#68) `download` reads the signed `checksums.txt` before anything about the package, picks the Windows installer from the signed list, and fails with `Unsupported::MissingAsset` inside its error when the release doesn't sign or attach this installation's download, so an app can tell it from a broken download.
